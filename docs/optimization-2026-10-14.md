## 一、性能

| 问题（评估时） | 优化后 |
| --- | --- |
| 菜单栏 App 每 2 秒请求一次 `/api/health`，不论是否可见；日志 26.5 万行 health（占 99%，16 MB 且不轮转）；打开菜单一次发 4 个请求 | 统一的 `ServiceHealthMonitor`：启动、停止、生成中 1.5 秒；窗口可见或菜单打开 5 秒；后台空闲 30 秒；不可达时 2→4→8→30 秒退避；请求未返回不叠加；打开菜单只发 1 个 health 请求，其余每 15 秒最多一次。估计日请求量从约 4.3 万次降到约 3 千次 |
| uvicorn 默认访问日志、无轮转；服务自身 `LOG.info` 丢失 | `logs/service.log` 5 MB × 3 轮转；成功的 health 及各类状态轮询不再记录；App 日志超过 10 MB 启动时轮转；worker 与 whisper 日志启动时轮转 |
| `/api/health` 在事件循环里同步请求 whisper-server（最长 0.5 秒）并做多次文件检查 | STT 就绪状态缓存并由后台线程每 10 秒内复核；文件检查缓存 30 秒；health 与 runtime 共用一个构建函数 |
| 长书 manifest 每段生成整文件重写 3 次（带缩进），全局一把锁；读取再深拷贝。500 万字书一次约 0.3–0.5 秒 | 内存缓存 + 每本书独立锁；紧凑 JSON、原子写入（唯一临时名 + fsync）；生成中段落状态最多每 1.5 秒合并落盘，状态变化、停止、关闭时立即落盘。16k 段的书：读取 9 ms、列表 2 ms、增量进度 3 ms、保存进度 0.5 ms |
| 阅读器每 2 秒保存进度（暂停时也保存），服务端重写整本并回传整本；块之间还要等它完成 | 进度单独存 `playback.json`，接口只回 `{ok, playback}`；只在真正播放且位置变化时保存（5 秒节流，换块即时），暂停、停止、关页时补存一次；块之间不再等待 |
| 整书生成时阅读器每 1.2–1.6 秒拉整本书（大书约 21 MB）并重建全部段落 DOM | 新增 `/progress?since=<revision>` 只返回变化的段落状态；只更新变化块的状态；章节分组线性计算；超过 400 块的章节按当前位置窗口渲染；书架列表只返回摘要 |
| 取消流式生成会杀掉 worker 进程，下一段要重新加载模型 | 关闭连接后最多等 3 秒确认 worker 空闲，空闲则复用；仍在忙才重启该通道。顺带修复：之前关闭连接并没有真正关闭 socket |
| 主进程为 PCM 转发加载 torch，每块音频约 8 次拷贝和一次有损浮点往返 | 主进程不再导入 torch；int16 PCM 原样透传；流式音频与保存的 WAV 逐样本一致 |
| 登录中间件用 `BaseHTTPMiddleware`，每个 PCM 分块经过额外的内存流，每个请求取一次锁读 epoch | 改为纯 ASGI 中间件，epoch 无锁读取；鉴权语义不变 |
| 长时间阻塞等待（播放租约、STT、逐块取音频）占用 asyncio 默认线程池（约 20 线程），排队多时可能互相饿死 | 独立的 96 线程池；流式音频改为异步等待，不再每块切线程 |
| 流式结束后播放租约仍保留 900 秒，外部客户端不释放会挡住其他播放 | 正常结束后缩短到剩余可听时长 + 10 秒 |
| 启动时重写最多 2 万个任务 manifest；STT 上传最多在内存中保留两份 500 MB；存储统计每分钟全量遍历 | 启动只加载最近 1000 个并只重写被标记中断的；STT 从临时文件流式上传；存储统计复用未变化目录的大小，每 10 轮全量一次 |

## 二、生成效果

| 问题（评估时） | 优化后 |
| --- | --- |
| 文档模式 token 上限按 0.256 秒/字计算，慢语速、数字和英文缩写会截掉句尾，且无检测 | 上限 0.5 秒/字 + 4 秒；用满 98% 视为可能截断，换种子以 1.5 倍上限重试一次；重试失败保留第一版而不让整本书失败。worker 的失控保护不会在调用方明确给出的上限内误判 |
| 章节标题和正文、段落之间无停顿地连读（“风起他说”） | 段落边界独立成块，短段落合并时用换行连接；合成时在缺少句末标点处补“。”；记录每块是句末、段末还是章末 |
| 英文句子不切分，超长时在单词中间硬切 | 英文按 `.!?` 加空白切句（含缩写保护）；超长句优先在逗号、顿号、冒号、破折号、空格处切，绝不切在字母数字中间；右引号、括号跟随前句；过短尾块并入前块 |
| 各段音量不一致，超限样本硬削波 | 整书段落：去直流、首尾静音修剪（保留 60/100 ms）、5/10 ms 淡入淡出、语音 RMS 归一到 -20 dBFS（±10 dB 内）、峰值限制 -1.5 dBFS |
| 段落之间停顿长短随机 | 句末 0.3 秒、段末 0.6 秒、章末 1.0 秒 |
| 整书 AAC 用 `-c copy` 拼接，每段多约 25–38 ms 空白并累计时间漂移 | 先按真实样本数裁掉每段编码填充，拼成 PCM 后统一编码一次；测试中合并后时长与各段之和误差在 60 ms 内 |
| 编码固定 80 kbps 并上采样到 48 kHz | 24 kHz 原生采样、96 kbps；有 AudioToolbox 编码器（`aac_at`）时优先使用 |
| 语言写死 Chinese，英文书也按中文读 | 按文本自动识别中文、英文、日文、韩文，其余交给模型自动判断；worker 按请求语言生成。旧项目保存的 Chinese 设置保持不变 |
| 部分后备采样参数仍是 temperature 1.7、top_k 25 | 统一为 Qwen3-TTS 推荐值 0.9 / top_p 1.0 / top_k 50 / 重复惩罚 1.05 |
| 短句失控时可能生成 30 秒以上的杂音才中止；非流式无“过早结束”检测 | 失控预算为 4 秒 + 0.5 秒/字（最少 6 秒）；非流式输出明显过短时换种子重试一次 |
| Markdown 原样送入模型 | 导入 `.md` 时去除标题、强调、列表、链接、图片、代码块和网址；合成前再做全角数字字母归一、省略号合并 |
| 默认块长 180–200 字，最大 500 | 服务端默认 160、上限 300 |

## 三、UI 逻辑

**小说阅读器**

- 整书生成中切换书籍，按钮卡死且之后弹出旧书的错误：上下文与书籍绑定，切书时重置，过期的打开请求和轮询被丢弃。
- 流式模式块间停顿（约首音延迟 + 1 秒）：当前块音频接收完毕即预取下一块，接在同一时间轴上无缝播放；预取失败时先让已到达的音频播完再提示。
- 已生成 AAC 模式块间停顿：第二个音频元素预加载下一段，结束时切换。
- 块间暂停后会自动恢复、加载中重复点击会重启整轮、下一块不跨章：改为明确的播放状态机（空闲、起播、播放、暂停、块间、停止中），上/下一块跨章节，起播中忽略重复点击。
- 流式倍速会变调：流式模式固定 1×，界面提示；AAC 模式保留变速不变调。
- 错误恢复：状态轮询和心跳失败重试 3 次（退避）；停止先在本地立即生效；音频错误会复位按钮；区分“服务重启”“被其他客户端停止”“连接中断”。
- 编辑模式下文字被定时刷新冲掉、整章 `aria-live` 反复朗读：已修复，改为小型播报区域。
- 新增：手机布局（< 760 px 抽屉式目录与书架、底部播放条）；快捷键 Space、←/→、J/K、[ ]、Esc；块使用 roving tabindex；空闲时 health 轮询从 5 秒降到 30 秒；删除书籍清理本地存储；同一文件可重复导入；在点击事件内启动音频以满足 Safari/WKWebView 自动播放规则。
- `web/studio/index.html`（2,610 行）已无任何入口，已删除，同时删除服务端相关模板代码。

**原生工作台与菜单栏 App**

- 服务重启后生成状态卡在“进行中”：`interrupted` 与 404 视为终态；连续失败 5 次停止轮询；轮询不再重叠。
- 提交中点击停止无效：提交返回后立即关闭该任务，不会播放。
- 崩溃恢复、菜单“启动”、上传重试可能并发启动第二个服务进程，原进程成为孤儿：服务生命周期改为状态机，并发启动合并为一次；启动中禁用启动/停止菜单项（之前的禁用代码实际不生效）。
- 重启服务会覆盖编辑器中未保存的参数：只有编辑器未改动时才同步服务设置。
- 健康状态每次都整体刷新界面：只在值变化时更新；录音计时每秒更新一次。
- 流式 PCM 播放无抖动缓冲：缓冲 0.35 秒后起播，按 ≥100 ms 合并调度，欠载后重新缓冲 0.25 秒；切换输出设备（如 AirPods）时重启音频引擎，不再卡住。
- STT 窗口连接状态只在打开时刷新、停止后立即重新转写的状态串扰：已修复。
- 阅读器 App 等待本地服务约 50 秒即放弃：QwenTTS 仍在启动时最多等 360 秒并显示已等待时长。
- App 构建开启 `-O -whole-module-optimization`。

## 五、未做与建议

- **`NativeStudioViewModel.swift` 拆分（约 2,100 行、80 个 `@Published`）**：没有编译器时风险过高，本轮未做。建议拆为 `ServiceStatusModel`、`GenerationController`、`VoiceEditorModel`、`ReferenceLibraryModel`、`ReferenceCaptureModel`、`ExternalAPISettingsModel`，外层保留一个薄的组合对象，并统一一个 async/await 的 `ServiceAPIClient` 替换约 25 处重复的请求解析代码。
- 路由层每个文件都解包约 20 个上下文字段，`create_app` 约 370 行，可在后续改为依赖注入并拆分。
- 流式模式的变速不变调需要时间拉伸（WSOLA/AudioWorklet），本轮选择固定 1×。
- 实时流式音频未做响度归一（需要前瞻，否则会忽大忽小）；整书与 AAC 结果已归一。
- 预设“选择即设为服务默认音色”的行为保持不变；如希望编辑预设不影响阅读器，可改为显式“设为默认”。
- 文档缓存常驻内存，500 万字的书估计约 100 MB，未实测。
- 参考音频仍未自动裁剪到 3–10 秒和做响度处理，ICL 参考文本仍需人工确认；建议上传后用本地 Whisper 自动转写供确认。
