# 音频服务场景清单与优化验收

本清单先定义预期，再对照实现和测试验收。范围包括当前原生工作台、菜单栏、阅读器、全书制作和外部 TTS/STT 调用。网络客户端自行缓存并播放的声音无法被 HTTP 服务直接停止；服务只能撤销租约、停止输出，配套客户端须响应停止状态。

## 基本规则

1. 出声权和 GPU 计算权分开管理。STT 只返回文字，不占用播放租约。
2. 内部连续听书优先；外部 TTS/STT 可排队，断开连接、超时、停止后退出。后台制书在段落边界与 STT 分享 GPU。
3. 同一时刻只运行一种 GPU 工作负载：TTS 按本机策略最多双路；STT 独占计算窗口。未测量混合负载前，不假定 TTS 与 STT 并行更快。
4. 任务保留提交时的模型/音色/seed 快照。更改服务设置作用于后续任务；活动任务不被中途替换模型。
5. 停止操作取消该轮排队请求与活动任务。新的显式启动/新请求属于新一轮；旧回调不得重建模型或覆盖新状态。
6. 长时间转码/合并不阻塞 HTTP 响应线程；失败状态可见，已有完成结果保留且可重试。

## 场景矩阵

| 场景 | 应有行为 | 核查/优化点 |
| --- | --- | --- |
| 流式听书 + 外部 STT | STT 等待内部播放结束/释放，朗读不断流 | 统一 GPU 调度、等待状态、断连取消 |
| 高质量块听书 + 外部 STT | 已缓冲音频照常播放，连续听书优先，STT 不插入出声队列 | 播放与计算权限分离 |
| 全书后台制作 + STT | 当前 TTS 段落完成后给 STT 独占窗口，之后续作 | 避免 STT 永远饥饿 |
| STT 进行中 + 新 TTS | TTS 排队，已有下载音频可继续播放 | STT 与 TTS GPU 不重叠 |
| 多个外部 STT 同时到达 | 有界等待、串行转写、各请求对应自己的结果 | 单次启动、取消和容量限制 |
| STT 冷启动期间再次启动 | 共用同一次模型加载 | 不生成重复进程 |
| STT 加载/转写中停止 | 当前处理终止，旧排队请求退出 | 不因旧请求再次自动启动 |
| STT 请求等待期间断网 | 撤回计算申请 | 不在稍后后台偷跑 |
| STT 等待超时/队列满 | 返回明确可重试错误 | 不无限占线程/内存 |
| 内部朗读 + 多个外部 TTS | 外部按队列等候，内部不会因公平额度死锁 | 被播放阻塞的外部任务不阻塞内部 |
| 多个外部音频都已生成 | 只有一个播放租约 | 客户端配合续租/释放 |
| 播放客户端关闭/崩溃 | 租约到期或断连释放 | 不永久阻塞后续客户端 |
| 全局停止后旧客户端重连 | 旧播放 epoch 失效 | 不能重新取得已撤销的播放权 |
| 工作台试听/参考试听 | 单端本地播放器停止旧音频再启动 | 多端须使用服务播放协议 |
| 生成中切换模型 | 等当前模型活动 session 结束后切换 | 不卸载使用中的模型 |
| 模型 A 持续有请求，B 排队 | B 在有界时间内得到机会 | 防止同模型新请求插队饿死切换 |
| 模型加载期间停止 | 取消加载/失效旧结果 | 防止停止后模型复活 |
| 停止后立即重新启动 | 旧任务 finalizer 不减少新任务计数 | 按轮次隔离生命周期 |
| 修改工作台参数但未应用 | 菜单刷新不覆盖草稿 | 只读状态和应用动作分离 |
| 应用新语音/seed 后仍有旧任务 | 旧任务用旧快照，新任务用新配置 | 不在任务执行时重读可变默认值 |
| 书籍从旧模型切到新模型制作 | 性能策略与最终提交模型一致 | 不先应用旧模型参数 |
| 性能测试 + 普通生成/STT | 测试独占 GPU，普通任务排队 | 测试取消可退出 |
| 两人同时请求同块 AAC | 单次转换、完整后发布 | 避免半成品被下载 |
| AAC 转码慢/失败/超时 | 健康检查和停止仍能响应，失败可重试 | 后台线程、有超时、临时文件清理 |
| 全书段落完成但合并失败 | 明确失败，完成段落仍保留 | 支持只重试合并 |
| 全书合并中停止/删除 | 停止优先，旧结果不得覆盖新状态 | 文件/状态锁顺序 |
| 生成中删除/编辑小说 | 拒绝不安全操作或停止后再操作 | 不删除工作线程仍引用的文件 |
| 删除被书籍或排队任务引用的音频 | 明确阻止并说明引用者 | 不能只检查预设 |
| 改名/隐藏已有音频 | 保持 ID/路径与任务参数稳定 | 只变更显示信息 |
| 上传大参考音频 | 限量读取并拒绝超限 | 防止内存和磁盘累积 |
| 临时参考上传后失败/关闭 | 清理属于任务的临时输入 | 不删用户库文件 |
| 服务重启时仍有未完成任务 | 标记中断，制书保留可恢复进度 | 不显示无工作线程的 running |
| 更新 App 但后台未更新 | 验证实际接口能力，明确版本不兼容 | 不能只检查 health=ready |
| 环境文件缺失/迁移安装 | 原生两应用与服务缺省端口一致 | 避免服务运行但阅读器连不上 |

## 验收记录

### 已落地（2026-09-06）

- 统一 TTS/STT/性能测试的 GPU 调度。STT 最多 16 个在途请求，计算等待最长 600 秒；队列满返回 429，服务停止返回 503，等待超时返回 504。STT 等待时，上传内容保留在框架的临时文件中，取得计算窗口后分块读取，避免整批等待请求同时持有大音频字节串。
- 阅读器增加持续听书预约（3 秒心跳、12 秒到期），跨段落空隙保持优先级；旧播放轮次、过期异步请求、停止后回调均不能接管新一轮播放。出声仍由独立播放租约控制。
- 模型切换按等待顺序准入，同模型请求不能一直插队；加载、停止、重启使用轮次隔离，旧 session 释放不会扣减新 session。实际执行模型使用自己的性能策略。
- STT 启动单飞，停止时等待旧子进程退役后才能再绑定端口；菜单显示转写运行和等待状态。菜单刷新服务信息不覆盖工作台尚未应用的参数草稿。
- 流式 PCM 不再因为内存队列达到 64 块而丢弃旧音频，改用可落盘缓冲（内存阈值 512 KiB，每任务总上限 64 MiB）；超限明确失败，不静默丢音。
- AAC 按任务与码率合并重复转换请求，在后台执行，完整后原子发布；转码有超时，全局停止/任务关闭会取消对应子进程。全书普通暂停保存当前活动段落，强制停止则终止转码；合并失败保留已完成段落，可重试合并。
- 删除参考音频前检查预设、书籍和排队/活动任务引用；临时上传失败后清理自有文件。两个原生应用缺省端口统一。

### 验证

- Python 全量测试：**66 passed**。包括调度死锁、STT 断连等待取消、停止与启动重叠、模型切换公平性、AAC 单次转换/取消/失败清理、真实 ffmpeg 编码、子进程超时与强制回收、全书恢复、播放 epoch、PCM 完整性等。
- Swift 生产 ViewModel 回归程序通过，验证参考音频改名与只读服务状态刷新不覆盖编辑草稿；菜单栏应用与独立阅读器均构建成功并安装到 `/Applications`。
- 阅读器 JavaScript 语法检查、`git diff --check` 通过。
- 已完成真实 Metal 组合验证：保持连续听书预约 → 外部 STT 排队 → 同时提交 Qwen 0.6B/1.7B 各一项非流式任务 → 两模型分别完成 → 各导出 AAC 80k → 释放预约 → 真实 STT 返回文字结果。服务已应用设置未改变，临时音频清理，全程未播放验证音频。可用 `scripts/check_live_concurrency.py --live` 在空闲服务上复验。

### 边界与后续测量

- 此清单区分已实现的调度保证与外部环境限制，不代表所有硬件/第三方客户端组合均已覆盖。原生界面未完成自动化点击验收，本轮使用生产 ViewModel 测试及构建验证。
- 本轮未重新测量 TTS+STT 混合 GPU 吞吐与峰值内存；默认不让两种推理重叠。现有 TTS 同模型双路能力保留，不声称混合并行更快。
- 连续听书期间外部 STT 可能达到等待上限；客户端应处理 504 并重试。STT 已进入实际推理后，单纯 HTTP 断连不保证立即终止推理（完成结果不再交付）；显式停止 STT/全局停止会关闭其工作进程。
- 模型构造阶段尚未交给管理器的底层加载不能保证瞬间抢占；停止会使加载结果失效并清理，但完成停止可能等待底层加载返回/超时。
- 已经下载到第三方播放器的音频，服务无法直接静音。外部客户端必须遵守播放租约、心跳和 epoch 撤销协议；独立本地参考试听也不等于跨程序全局播放互斥。
- 网络上传的硬限制在请求解析后检查，不是反向代理级的上传速率/磁盘配额；公网部署还应设置网关限额。本机服务测试不替代公网安全评估。
